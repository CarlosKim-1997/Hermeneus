# T-030 — 실제 서비스 레퍼런스 기반 UI 적용

2026-10-20 · 로컬 검토판 · 사용자/실제 Chat 테스트는 보류

## 범위와 근거

사용자의 이번 요청에 따라 실제 서비스의 공개 UI 사례를 조사하고 로컬 UI에 적용했다.
기준 HEAD는 `9979e7c49bfc45b14dd186911c4db43da9411736`이며, T-028/T-029의
미커밋 작업을 유지한 작업 트리다. GitHub/배포 상태를 새로 검증한 보고서가 아니다.
Governance·활성 Canon은 변경하지 않았다.

공식 출처와 관찰/문서/설계 가설의 구분: `docs/UX_REFERENCE_STUDY.md`.
Linear·Notion·Typeform은 공식 페이지의 제품 화면 예제를 눈으로 확인했고,
Loom의 챕터 동작은 공식 설명을 읽었다. 각 제품에 가입해 전체 흐름을 체험한
것으로 주장하지 않는다. 공개 화면 증거: `dist/t030-references/`.

## 적용

| 제품 흐름 | 가져온 원리와 구현 |
| --- | --- |
| 작업 공간·전달함 | Linear의 작업 맥락/속성 분리 → 고정된 사이드바, 목록, 상태 필터, 이름·관리 번호 검색, 행별 다음 행동. 모바일에서는 가로 탐색과 세로 목록. |
| Sender 준비 | Typeform의 목적·진입 행동 명확화 → 두 개의 번호 있는 작업 영역: 내 AI용 안내문, 가져온 JSON. 세 가지 준비 기준과 원문 수집 경로는 보조 영역. |
| 확정·공유 | 문서와 작업 분리 → 전달 내용은 읽기용 문서, 링크 생성·해제는 별도 영역. 게시 의미는 그대로. |
| Receiver | Notion의 목차와 Loom의 선택적 탐색 원리 → 고정 버전 문서·항목별 이동, 옆의 내 AI/답변 검사/사이트 질문 안내. 자료 전송과 답변 검사는 분리. |
| 전체 화면 | 인디고 행동 색상, 중립 배경, 일관된 글자·경계·포커스. 검토·계정·로그인·오류 상태에도 같은 계층 적용. |

`PublishedDocument`는 owner/share/publication에서 재사용한다. 문장·항목 순서·분류·중요도는
그대로 렌더링하며 목차에만 문자 단위의 원문 발췌를 사용한다. 새 요약이나 요청을 생성하지
않는다. `NewHandoffWorkspace`는 실제 앱과 합성 미리보기에 동일하게 사용한다.

## 자체 리뷰와 수정

- 검색/필터는 이미 소유권 검사를 통과한 목록 props만 브라우저 메모리에서 처리한다.
  외부 호출, URL 검색어, localStorage, analytics를 추가하지 않았다.
- 확정본 보유 필터는 게시 버전의 존재를 말한다. 공유 링크 활성 여부나 새 초안의 부재를
  추정하지 않는다. title은 계속 명시적 선택에 의한 비공개 탐색 이름이다.
- 목차 링크는 고정된 항목 인덱스만 사용한다. 토큰·질문·답변을 URL에 추가하지 않는다.
  이동 대상은 키보드 포커스를 받고 원문은 HTML로 실행하지 않는다.
- 외부 AI 전송 고지, 검증마다의 동의, provider-off/INDETERMINATE, 결과와 검사 원문의
  결합·수정 시 무효화, 고정 버전과 삭제 확인을 유지했다. 인증·DB·권한 계약은 바꾸지 않았다.
- Share 페이지에 아직 자동 ChatGPT 연결이 통합되지 않았음을 표시했다. 합성 MCP 위젯을
  실제 공유에 연결된 기능처럼 광고하지 않는다. 실제 Chat 테스트도 재개하지 않았다.
- 작은 화면에서 이전 CSS의 `column-reverse`가 새 전달 목록의 제목·아이콘을 뒤집는 것을
  스크린샷으로 발견해 명시적 모바일 grid로 수정했다. 목차 숫자 줄바꿈과 문자 발췌도 보완했다.
- E2E의 예전 메뉴/단계 제목 선택자를 수정하고, 목차 발췌와 본문에 같은 문장이 있는
  검사는 본문으로 한정했다. Next 개발 서버의 비동기 게시·원문 삭제 완료가 5초 안에
  도착하지 않은 사례는 해당 완료 상태 대기를 30초로 변경했다. 완료·권한 검사는 제거하지 않았다.
- 동시 Next E2E 실행에서 자원 경합이 관찰되어, 해당 시험 컨테이너만 종료·정리하고
  단일 환경으로 재검증했다. 내부 리뷰이며 제3자 독립 보증이나 전체 접근성 인증이 아니다.

외부 네트워크를 끊고, 앱 E2E는 외부 접속 없는 내부망의 새 DB만 사용했다.
시험 소유 컨테이너·일회용 volume·내부망만 정리한다. 서비스용 실제 DB와 OAuth는 건드리지 않았다.
