# 공유 건별 MCP 위임과 답변 비영속 반환 제안

상태: **위임 규칙·수명·보안 기록 정책 사람 승인 완료, 구현 검증 전**. 작성일: 2026-10-19.
기준 HEAD: `9979e7c49bfc45b14dd186911c4db43da9411736` 및 T-028 합성 실험의 로컬 변경.
이 문서는 구현·외부 설정·배포·DB 변경·유료 호출 권한을 부여하지 않는다.

후속 사람 승인: 위임 30분, OAuth 60분/자동 갱신 없음, 반환 티켓 60초/1회,
답변 비영속 및 보안 메타데이터 정리 정책을 승인했다. 먼저 합성 UI에서 사이트로
POST하는 시험, 가능하면 로컬 권한·반환 구현과 회귀 검증을 허가했다.
현재 문서의 ‘제안’ 수치는 그 승인 내용을 보존한다. 이 승인을 실제 OAuth 서비스
설정·DB 적용·실데이터·유료 호출·Git 원격 권한으로 확장하지 않는다.

## 권장 구조

기존 `/share#…` 링크는 그대로 둔다. 유효한 bearer로 접근한 수신자가
명시적으로 선택한 공유 건만 자기 ChatGPT 연결에 잠시 위임한다.
원래 Share 비밀은 Hermeneus 웹과 서버 사이에서만 사용한다.
MCP는 제한된 연결 인증과 위임 기록을 함께 확인한다.

선택 답변은 MCP의 Hermeneus 검토 위젯에 보여준다. 위젯에서 사용자가 누르면
서명된 일회성 반환 티켓과 답변을 **HTTPS POST 본문**으로 Hermeneus 반환 화면에
보낸다. URL에는 본문·암호화 본문·본문 복원 키·반환 티켓을 넣지 않는다.
서버는 요청 중 검증 후 `no-store` HTML로 답변을 표시하고 본문을 보관하지 않는다.
의미 검증은 별도 화면의 원문 확인과 매회 동의를 거친 다음에만 실행한다.

**첫 기술 Gate:** 일반 Chat의 MCP Apps 위젯에서 사용자가 누른 form POST가
허용된 Hermeneus 사이트의 새 창으로 이동할 수 있는지 합성 자료로 확인한다.
MCP Apps UI와 도구 호출 지원만으로 이 동작까지 지원된다고 추정하지 않는다.
미지원이면 위젯 안에서 원문 확인·검증하는 축소안을 별도로 제시한다.
별도 사이트 복귀를 성공했다고 보고하거나 답변 임시 저장으로 우회하지 않는다.

## 유지하는 권위와 필요한 비준

| 기준 | 유지할 동작 |
| --- | --- |
| D-008 | 공유 링크의 bearer 접근 유지. Creator 로그인·Receiver 가입을 웹 공유 접근 조건으로 추가하지 않음. 하나의 capability는 한 Published 버전만 가리킴. |
| C-005 | 원래 Share bearer는 모델·도구 인자·URL query·애플리케이션 로그·영속 저장에 넣지 않음. 기존 capability의 대상과 token hash를 변경하지 않음. |
| D-013 / C-012 | 외부 AI 출력은 비신뢰 입력. 정확한 제출문과 Published 버전만 검증. 위젯·digest·프롬프트만으로 ALIGNED나 이해 완료를 주장하지 않음. |
| D-009 / C-008 | 공유 취소·Handoff/계정 삭제에 종속. 이미 공개된 Canon의 의미와 삭제 범위를 변경하지 않음. |
| 기존 위임 계약 | Hermeneus는 답변·질문·동의 선택을 영속 저장하지 않음. 유료 호출은 기존 승인 범위 안에서만 수행. |

D-008은 보호된 공유 작업마다 원래 bearer를 해석하는 방식을 명시한다.
새 MCP 요청은 그 bearer 대신 **명시적으로 발급한 종속 위임 자격**을 제시하므로,
일반 리팩터링으로 처리하지 않는다. 기존 링크 접근을 유지하면서 이 종속 자격을
허용하는 좁은 규범 결정의 사람 비준이 필요하다. 현재 Canon을 조용히 고치지 않는다.

비준할 문구의 골자:

> 유효한 Share bearer 소지자는 특정 Published 버전의 Canon 조회와 선택 답변
> 반환을 본인이 연결한 AI 클라이언트에 일시 위임할 수 있다. 위임은 원래
> capability의 취소·대상 삭제·만료에 종속되며, 원래 capability를 변경하거나
> Creator 권한을 부여하지 않는다. 위임 없이 기존 웹 공유 접근은 계속 가능하다.

OAuth는 MCP 연결을 구분·인증하기 위한 수단이다. OAuth 로그인 성공이나 Creator
계정 소유만으로 Handoff 접근권을 발급하지 않는다. 웹 공유 접근과 계정 필수화를
혼동하지 않는다. 초기 Alpha는 가입 없는 익명 연결 주체를 제안하며, 별도 이메일·
프로필 정보는 요구하지 않는다. 익명 연결 주체도 보안 식별자이므로 수명·삭제를 둔다.

## 사용자 흐름

1. 수신자가 기존 공유 링크를 연다. 브라우저는 fragment를 지우고, bearer를
   요청 본문으로 보내 기존 공유 권한과 정확한 Published 버전을 확인한다.
2. 수신자가 **내 ChatGPT에 이 Handoff 연결**을 누른다. 보낼 Canon 범위와
   개인 ChatGPT에서 처리·보관될 수 있다는 안내를 확인한다. 아직 유료 검증은 없다.
3. 처음에는 MCP 플러그인을 연결한다. OAuth 승인 페이지는 같은 Hermeneus
   브라우저에서 1번의 bearer 소유를 다시 확인하고 OAuth 흐름에 결합한다.
   bearer를 리디렉션 URL이나 OAuth state에 넣지 않는다. 페이지를 잃었으면
   원래 공유 링크를 다시 열도록 한다. 자동 연결이나 기존 쿠키 존재를 가정하지 않는다.
4. 서버가 해당 연결과 해당 공유 건에만 종속된 위임을 발급한다. 수신자가
   버전·대상을 확인하고 새 Chat을 연다. 프롬프트에는 비밀이 아닌 공개 참조만 둔다.
   플러그인은 현재 관찰된 방식대로 사용자가 직접 선택한다.
5. AI가 MCP로 승인된 Canon을 조회하고 설명한다. 다른 공유 건으로 자동 전환하지 않는다.
6. 수신자가 답변을 지정해 가져오기를 요청한다. MCP는 제출문을 구조 검사하고
   원문·고정 버전을 보여주는 Hermeneus 위젯을 반환한다. 전체 대화는 요청하지 않는다.
7. 위젯의 **Hermeneus에서 확인**을 누르면 답변과 일회성 티켓을 POST로 보낸다.
   반환 사이트는 부모 공유 권한과 티켓·본문 결합을 확인한 뒤 원문을 표시한다.
8. 사용자는 사이트에서 원문과 매회 외부 처리 동의를 확인하고 검증을 누른다.
   답변 변경은 확인·동의·이전 결과를 지운다. 검증 전후 모두 공유 취소·삭제를 확인한다.

원래 Chat의 임의 답변을 서버가 직접 읽을 수 있다는 전제는 두지 않는다.
모델이 전달한 답변과 사용자가 의도한 답변의 일치는 검토 화면에서 확인한다.
Markdown 강조·줄바꿈 차이는 숨기거나 정규화하지 않는다.

## 공유 건별 위임 자격

### 발급과 OAuth 결합

- OAuth 2.1 authorization code + PKCE S256, 정확한 redirect allowlist,
  state·issuer·audience·scope 검증을 사용한다. 검증된 구현체를 우선 평가한다.
  현재 Creator Google 로그인 토큰을 MCP 토큰으로 재사용하지 않는다.
- 익명 연결의 앱 인증 세션과 OAuth 교환에는 최대 **60분**, 자동 refresh token
  미발급을 초기 제안으로 둔다. 만료되면 명시적 재연결이 필요하다.
- 공유 페이지에서 OAuth 주체와 bearer 소유를 같은 브라우저의 일회성 nonce 및
  CSRF 검증으로 결합한다. 서버에는 원래 bearer나 되돌릴 수 있는 bearer 복사본을 두지 않는다.
- 연결 완료 후 새 Chat에 넣는 `contextRef`는 OAuth 연결 안에서만 해석되는
  비밀 아닌 선택자다. 이것만으로 조회·반환·권한 획득은 불가능하다.

### 권한 및 기본 수치 제안

| 항목 | 제안 |
| --- | --- |
| 위임 단위 | 원래 Share capability 하나와 정확한 Published 버전 하나 |
| 위임 수명 | 절대 30분. 부모 권한·OAuth 세션 만료보다 길 수 없음. 자동 연장 없음 |
| 허용 | 해당 Canon 조회, 해당 Canon에 대한 선택 답변 검토 준비 |
| 금지 | 다른 Handoff 목록·검색, 소스/삭제된 provenance, Draft, 편집·발행·삭제, Creator 작업, 모델 단독 유료 검증 |
| 요청 식별 | 인증된 연결 주체 + 비밀 아닌 contextRef + 활성 위임 |
| 동시 공유 | 공유 건별 별도 위임. 계정 단위의 가변 ‘현재 Handoff’ 사용 금지 |
| 원래 공유 취소 | 다음 접근과 진행 중 반환·검증의 결과 공개를 차단 |
| 위임만 해제 | 원래 Share 링크는 유지 |
| 저장 | 연결·자격 해시, 부모 capability 참조, 연결 주체, 범위, 버전, 만료·취소 등 보안 메타데이터만 |

모든 작업에서 부모 capability의 현재 활성 상태와 삭제 상태를 재조회한다.
오래 살아 있는 서명 토큰만 믿지 않는다. 동시에 공유가 취소되면 결과 공개 시점의
재검사 또는 짧은 원자적 권한 판정으로 차단한다. 이미 AI에 전달된 Canon의 사본은
소급 회수할 수 없으며, 미래 조회·반환을 막는 것으로 설명한다.

## 답변을 URL에 넣지 않는 반환 계약

제안 도구명은 `get_handoff_packet(contextRef)`와
`prepare_answer_return(contextRef, submission)`이다. 실험의 `check_synthetic_answer`를
실제 유료 검증 성공처럼 확장하지 않는다.

`prepare_answer_return`은 packet/submission v0, 정확한 pub ref와 digest,
문자 수·요청 바이트 제한을 검사한다. 위젯에는 원문을 전달하되, 모델이 원문이나
credentials를 새로 재작성해 링크에 붙이지 않도록 반환 도구 계약을 분리한다.
`content`/`structuredContent`에는 최소 상태·공개 버전 정보만 두고,
UI용 `_meta`에는 검토할 답변과 반환 티켓을 둔다. `_meta`가 모델에 숨겨진다는
것은 OpenAI 호스트에서 보관되지 않는다는 보장이 아니다.

### 일회성 반환 티켓

- 256비트 난수 jti와 서명된 claim: 용도, 위임 참조, 대상 origin/path,
  부모 공유 참조, 버전, submission의 JCS SHA256, 발급/만료 시각.
- 기본 수명 **60초**, 한 번만 소비. 서버에는 jti의 hash와 소비/만료 상태만 둔다.
  답변·질문·동의·본문 digest의 DB 영속 보관은 하지 않는다.
- raw 티켓은 widget 전용 결과와 HTTPS POST 본문에서만 취급한다.
  서명·digest는 본문 변경 차단용이며 사용자 동의의 증거가 아니다.
- `/receiver/return`은 고정된 POST 목적지다. 티켓·서명·수명·부모 권한·본문 digest를
  확인하고 원자적으로 소비한다. 잘못된 티켓·재사용·다른 Canon은 공통 실패 처리한다.
- 이 티켓도 자격 증명이다. OAuth 주체에 속한 위임에서 발급하지만, 반환 단계는
  티켓 소지에 의한 제한된 bearer 전달이다. 사람의 신원이나 특정 브라우저 계정을
  증명한다고 주장하지 않는다. 단순 Origin·Referer 검사나 숨은 필드를 인증으로 쓰지 않는다.

### 반환 사이트와 검증

POST 응답은 외부 리소스와 분석 스크립트 없는 검토 문서로 제한한다.
답변을 안전하게 이스케이프하고 실행하지 않는다. 응답과 요청 처리에 no-store,
no-referrer, 엄격한 CSP와 본문·오류·트레이스 로그 제외를 적용한다.

원문 표시와 함께 답변 digest에 결합된 별도 단기 검증 nonce를 발급한다.
모델 도구는 이 화면의 확인·동의 UI를 생략해 유료 검증할 권한을 갖지 않는다.
검증 nonce는 새 반환 화면에서 설정한 안전한 first-party 세션 및 CSRF 방어와
결합한다. 실제 검증 요청은 해당 화면에서 확인한 정확한 본문을 POST한다.
동시 제출·재시도에서도 nonce 소비와 예산 예약이 중복 실행되지 않아야 한다.

새로고침이나 창 닫기 후 답변을 다시 조회하는 API는 제공하지 않는다.
티켓 소비 후 네트워크가 끊어져도 서버 저장본을 복구하거나 자동으로 재전송하지 않는다.
수신자는 Chat에서 다시 가져오기를 명시적으로 요청한다. 페이지에서 뒤로 이동해
다른 답변을 선택하면 이전 결과·동의를 복원하지 않는다.

## 비영속 범위와 메타데이터 수명 제안

| 대상 | 허용 위치와 수명 |
| --- | --- |
| 답변·질문 | 요청 처리 중 서버 메모리, 표시 중 브라우저 메모리. DB·Redis/KV·큐·파일·분석·추적·widget state·브라우저 storage·URL에 저장하지 않음 |
| 동의 선택 | 현재 확인 화면과 해당 검증 요청에서만 사용. 영속 이력 미보관 |
| 권한·티켓 메타데이터 | 해시와 접근 통제 정보만. 원문 없음. 만료 후 24시간 이내 정리 제안. 부모 Handoff/계정 삭제 시 해당 공유의 위임·티켓·연결 매핑 삭제. 다른 공유에 사용 중인 OAuth 연결은 유지 |
| 유료 예산 기록 | 기존 승인된 예산·멱등 처리 규칙 유지. 질문·답변·동의 본문 추가 금지 |
| 결과 | 현재 화면에 해당 제출문과 함께 표시. 새 답변·버전·접근 종료 시 무효화 |

비영속은 Hermeneus의 저장 경계를 뜻한다. ChatGPT 대화·도구 데이터의 자체 보관,
브라우저의 메모리/BFCache·POST 재전송 동작, 사용자의 복사/저장은 별도다.
HTTP no-store만으로 브라우저의 모든 흔적이 없어지거나 물리적 메모리가 즉시
소거된다고 주장하지 않는다. 브라우저 복원 시험과 화면 초기화 정책을 검증한다.

## 합성 구현 순서와 통과 기준

1. **UI 전송 PoC:** 일반 Chat 위젯 → 사용자 클릭 → 고정 사이트 POST → 원문 표시.
   host sandbox의 form/pop-up 지원, 실제 Origin, 쿠키 의존성, 새로고침을 관찰한다.
   새 창 POST가 불가하면 별도 사이트 자동 반환 Gate는 BLOCKED다.
2. **로컬 위임:** 실제 DB 대신 테스트 저장소로 공유 A/B와 별도 익명 OAuth 연결을
   구성한다. contextRef 단독 접근, 다른 연결의 참조, 만료·scope 오용·발급 CSRF를 거부한다.
3. **반환 보안:** 서명·본문·Canon 변경, 만료·재사용·동시 소비, 원문 HTML 주입,
   위조 동의·유료 자동 호출, stale 화면/버튼, 실패 뒤 재전송을 부정 시험한다.
4. **삭제/취소:** 발급·조회·반환·검증 중 원래 공유 취소와 Handoff/계정 삭제를
   끼워 넣어 권한 잔존과 결과 공개를 차단한다. 위임 취소는 원래 링크를 바꾸지 않는다.
5. **실제 앱·합성 Handoff:** 승인된 인증 MCP와 DB 보안 메타데이터만 배포한다.
   기존 Alpha 보호 유지, 별도 MCP 진입의 인증·접근 범위를 검증한다.
6. **의미 검증:** 별도 승인된 호출 수·예산 안에서 실제 per-check UI를 시험한다.
   분석 불능·검증 실패는 INDETERMINATE. 불완전 coverage는 ALIGNED가 될 수 없다.
   판정 집계는 기존 v0.1 계약을 유지하며 출처의 사실성·사람 이해를 보증하지 않는다.

Codex 내부 적대적 리뷰와 해당 회귀 테스트를 수행한다. 내부 검토를 제3자 보증으로
부르지 않으며, 외부 ChatGPT 감찰이나 GitHub 승인 리뷰를 임의의 새 Gate로 추가하지 않는다.

## 승인 요청 목록

| 항목 | 승인할 내용 | 시점 |
| --- | --- | --- |
| 위임 규범 | 원래 bearer에서 파생되는 종속 MCP 권한 허용. 기존 웹 공유 접근·Creator 권한은 유지. 수명 30분, OAuth 60분/refresh 없음, 명시적 재연결 | 실제 권한 구현 계약 확정 전 사람 비준 및 필요한 Canon 반영 권한 |
| 보안 메타데이터 수명 | 답변 비영속 유지. 연결·티켓 hash/만료/소비 기록만 저장하고 만료 후 24시간 이내 정리 | DB 설계 확정 전 |
| 실행 위임 | 먼저 로컬·합성 UI PoC와 테스트 구현 허용. 사이트 POST 미지원 시 위젯 내부 대안은 별도 UX 승인 | 다음 개발 착수 시 |
| 외부 적용 | 검토된 OAuth 제공자/라이브러리·설정, 인증 MCP 노출 범위, plugin metadata/재연결, DB migration과 비밀 키 설정 | 구체 구성과 검증 결과를 갖춘 뒤, 외부 변경 전 |
| Git 및 release | 커밋·push·PR·병합·배포 각각 실제 승인 범위 확인. 실험의 무인증 공개 endpoint를 실데이터 서버로 바꾸지 않음 | 해당 단계 전 |
| 유료 검증·실제 자료 | 유료 합성 smoke 잔여 한도 확인, 추가 비용은 별도 승인. 실데이터는 저장·복구·개인정보/로그·접근 Gate 및 공개 범위 승인 | 각 사용 직전 |

새로운 외부 인증 서비스를 이미 선택·과금한 것으로 보지 않는다. 구현체·비용·실제
호스트 지원을 확인한 구체 구성으로 외부 적용 승인을 요청한다. 현재 문서 작성만으로
Canon·DB·Git 원격·플러그인·배포 상태를 바꾸지 않는다.
