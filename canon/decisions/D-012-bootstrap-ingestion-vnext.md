# Portable Canon Proposal ingress without mandatory source import

## Decision

Hermeneus accepts two distinct, provider-neutral ingress modes:

1. A **bootstrap-proposal path** in which the Sender supplies a Hermeneus instruction to the AI session in which the idea was developed and imports the structured Portable Canon Proposal generated there. This is the preferred vNext path.
2. An **imported-source path** in which Hermeneus imports actual conversation material, normalizes it, and may create an extraction proposal. This remains an optional supported capability.

A portable proposal is untrusted input, not Canon, an original conversation export, or evidence of Sender approval. Hermeneus validates the incoming proposal's structure, allowed roles, types, and referential integrity; it does not guarantee semantic fidelity to uncollected conversation history. The Creator must review or edit the resulting Draft and explicitly approve publication at the expected Draft revision. The external model is not a ratifying actor.

The bootstrap-proposal path must work without importing or inventing raw conversations, normalized source messages, or source-message provenance. **Original transcript NOT_COLLECTED**, **original transcript RETAINED**, and **original transcript ERASED** are distinct factual states. NOT_COLLECTED must never be represented as ERASED, and the proposal itself must never be mislabeled as a verified original transcript.

Actual retained source provenance, when present, remains subject to D-009, C-004, C-008 and C-009. Any separately persisted bootstrap submission is an erasable input artifact, subject to the Handoff and Creator data lifecycle; mere possession of its text does not establish correctness of the absent original conversation.

The core Handoff and Published Canon semantics are independent of the specific source AI provider. No undocumented scraping or fabricated provider export format is required or authorized.

## Context

D-002 mandated normalized conversation as the path into the handoff domain. The preferred vNext flow uses a structured proposal generated by the AI already holding the Sender's context. Legacy persistence and UI currently assume a source-conversation relationship; implementation migration is separate from this normative change.

## Rationale

Long-context reconstruction is delegated to the original AI when convenient, while preserving the human approval gate. Requiring Hermeneus to re-import source content is not fundamental to the authority model and increases ingestion and privacy burdens. Fabricated source messages would destroy the integrity of the existing provenance/erasure distinction.

## Consequences

- Preserve imported-source adapter and normalization paths as optional and valid for existing data.
- Implement a source-independent Handoff draft creation path in a separately authorized engineering phase.
- Do not label a structurally valid proposal as semantically verified.
- Preserve retained-source integrity, source erasure, whole-Handoff erasure and account erasure obligations.
