# Hermeneus UX 조사·개선 계획

2026-10-20 · T-029 · 비규범적 설계 문서. 설치된 Governance와 활성 Canon이 우선한다.

## 목표와 판단 기준

한 번 정리한 전달본으로 발신자의 반복 설명 부담을 줄이고, 수신자는 자신의
AI에서 맥락을 따라간다. Hermeneus는 발신자가 확정한 의미와 선택한 AI 답변의
정합성 확인을 연결한다. 회의 대체·이해 보증·시장 수요는 아직 입증되지 않은 가설이다.

핵심 질문은 “어떻게 예쁘게 보일까”와 함께 다음을 다룬다.

1. 처음 온 발신자가 자기 AI에서 준비한다는 점을 알아차리는가?
2. AI 제안과 자신이 확정한 전달본을 구분하는가?
3. 수신자가 첫 화면에서 요청·조건·미정 사항을 찾을 수 있는가?
4. 개인 AI에서 설명받는 경로와 사이트 질문 기능을 구분하는가?
5. 선택 답변만 검사하며, 검사되지 않은 내용·사람의 이해·외부 사실까지 보증하지 않음을 이해하는가?
6. 공유 해제·원문 삭제·전달 삭제·계정 삭제의 범위를 구분하는가?

## 조사 단계와 증거 수준

| 단계 | 방법 | 산출물·완료 기준 | 현재 범위 |
|---|---|---|---|
| 권위·제품 조사 | Canon, 실제 route/component, 기존 시험 기록 비교 | 약속 가능한 것과 미구현 기능 구분 | 이번 로컬 작업 |
| 전문가 점검 | 대표 시나리오로 인지적 walkthrough, 용어·위계·오류·접근성 확인 | 화면별 문제·근거·우선순위 | 이번 로컬 작업 |
| 구현·보강 | 실제 component로 UI 재구성, 안전한 상태·다음 행동 표시 | 기능 계약 유지, 모든 route/state 점검 | 이번 로컬 작업 |
| 자동 검증 | 합성 component fixture, 키보드·반응형·실패·지연 결과 검사 | 실행 증거, 실패 수정 | 이번 로컬 작업 |
| 실제 사용 관찰 | 발신/수신 역할의 과제 수행과 후속 질문 | 도움 없는 성공·막힘·오해 기록 | 소유자 재개 전 보류 |
| 반복 개선 | 관찰 문제를 위험·빈도·수정 비용으로 정렬 | 작은 수정 후 같은 과제 재검증 | 관찰 후 |

전문가 추정, fixture 시험과 실제 사용자 관찰을 별도 기록한다. 화면 코드를
읽었다는 이유로 사용성이나 제품 효용이 검증됐다고 쓰지 않는다. 외부 조사나
참가자 접촉, 분석 SDK·추적·녹화·실데이터 수집은 이번 작업에 포함하지 않는다.

## 대표 여정

### 발신자

전달함 → 새 전달 → 내 AI용 안내문 복사 → 맥락을 나누던 자기 AI에서 초안 생성
→ JSON 가져오기 → 미리보기·일시적 검토 메모 확인 → 초안 만들기 → 항목 분류·내용 검토
→ 전달본 확정 → 해당 버전의 링크 발급·복사 → 기존 메일/메신저로 전달.

원문을 직접 가져오는 경로는 보조로 유지한다. 이 경로의 원문 저장과 별도 AI 추출
전송 조건을 숨기지 않는다. private title은 opt-in이며 공개 의미에 포함하지 않는다.

### 수신자

공유 링크 → 버전·확정 내용 읽기 → 내 AI용 자료 준비와 외부 공개 확인 → 자기 AI에
자료 전달·질문 → 특정 답변 원문 선택 → 해당 원문만 검사 → 버전과 검사 범위를 확인.

사이트 내 질문은 보조 경로로 명시한다. 현재 서비스의 수동 복사 경로와 T-028의
ChatGPT 위젯 합성 prototype을 혼동하지 않는다. production의 자동 연결·자동 가입·
자동 plugin 선택은 이번 UI 작업으로 제공하지 않는다. T-028 실제 Chat 버튼 왕복은 보류다.

### 목표로 하는 MCP 경험 — 제품 연결 전 설계 대상

사용자는 수동 복사 왕복을 최종 주경로로 선택하지 않았다. 목표 흐름은 공유 링크
→ 짧은 요청·버전 확인 → 개인 ChatGPT 연결 → 새 Chat에서 설명 → 선택 답변의
Hermeneus 위젯 원문 확인·검사다. 최초 사용자에게만 가입·플러그인 연결 안내를
제공하고, 재사용자는 해당 공유의 권한 범위를 확인한 뒤 진행하도록 설계한다.
이는 현재 서비스에 구현됐다는 뜻이 아니며 T-028이 검증해야 할 기술·권한 경계가 남는다.

이번에는 현재 작동하는 수동 경로의 정보 위계를 정리한다. 후속 MCP 화면 설계는
연결 전/연결됨/권한 만료/해제/원문 선택 대기/의미 검증 미연결/판정 결과 상태를
포함한다. 연결 여부를 추정하거나 클릭만으로 설치·새 대화 전송이 완료됐다고 표시하지 않는다.
회신 수집·상대의 이해 확인·상호 합의 기록은 새로운 기능 제안으로 구분하며,
현재 검사 결과나 버튼 클릭으로 이를 대신하지 않는다.

### 관리·실패·복귀

임시 저장/미저장 → 중복 편집 충돌 → 확정 버전 고정 → 복사 실패/수동 복사
→ 잘못된 공유 링크 → 접근 해제 → 원문만 삭제 → 전달 전체 삭제 → 계정 삭제 중 재시도.

## 현재 관찰과 보강

| 우선순위 | 관찰된 문제 | 보강 방법 | 확인할 증거 |
|---|---|---|---|
| P0 | 원문 삭제·전달 삭제·접근 해제 범위 혼동 가능 | 범위별 문구와 별도 확인 유지, 되돌릴 수 없음 명시 | 확인 UI·기존 회귀 |
| P0 | 답변 수정 중 늦게 온 검사 결과가 새 원문에 붙을 수 있음 | 입력/연결 세대에 결과를 묶어 오래된 응답 무효화 | 지연 응답 시험 |
| P1 | Portable Proposal/Creator/Receiver가 주된 화면 언어 | 한국어 행동 중심 명칭, protocol과 enum 값은 유지 | 실제 component·접근성 이름 |
| P1 | 두 생성 경로가 동등하게 보임 | 내 AI 준비를 주경로, 원문 import를 펼침형 보조 경로 | 새 전달 화면 |
| P1 | 미리보기·저장·확정·공유가 구분되기 어려움 | 단계 표시, 저장 상태, 고정 버전과 링크 생성 분리 | 실제 흐름·상태별 fixture |
| P1 | 내 AI와 사이트 질문의 위계 부족 | 내 AI 경로를 먼저 강조하고 보조 기능 명시 | 수신 화면 |
| P1 | 판정 코드만으로 신뢰 범위 이해 어려움 | 평이한 판정 설명+원래 코드+검사 원문·버전 표시 | 실패·provider-off 상태 |
| P2 | 긴 기술 ID가 주된 제목/세션 정보 | 관리 정보에 배치, private 이름의 범위 표시 | 전달함·세션 |
| P2 | 화면 간 색·간격·동작 버튼의 일관성 부족 | 공통 토큰, 상태 badge, 버튼 위계, 입력·focus 스타일 | 전체 화면과 390px 폭 |

이 표의 사용성 문제는 전문가 평가 가설이다. 코드에서 재현한 결과 결합 문제만
동작 결함으로 구분한다. 인용·분류·우선순위·프로토콜 의미는 바꾸지 않는다.

## 화면·상태 조사 목록

- 로그인: 외부 로그인 / 개발용 / 사용 불가
- 전달함: 비어 있음 / 초안만 있음 / 확정 버전 있음 / private title 없음 / 긴 제목
- 새 전달: 안내문 복사·fallback / 초안 입력 / 잘못된 JSON / 미리보기 / 메모 확인 / private title 기본 미선택
- 검토: 원문 보관·삭제·미수집 / 빈 항목 / 저장 / 미저장 / 충돌 / 확정
- 확정·공유: 버전 읽기 / 링크 발급 / 단회 표시·복사 실패 / 사용 가능·해제
- 수신: 고정 버전 / 전체 항목 / 내 AI 자료 / 외부 공개 확인 / 사이트 질문·분류·근거
- 검사: provider off / per-check 동의 / 결과 없음·실패·불확정 / 원문 변경·지연 응답
- 관리: 원문만 삭제 / 전달 전체 삭제 / 계정 DELETE 확인 / 삭제 진행 중
- 공통: loading / error / not found / 키보드 focus / 작은 화면 / 긴 문장·URL

## 실제 사용 조사 제안 — 재개 후

첫 탐색 표본은 3쌍(발신자 3명, 배경에 익숙하지 않은 수신자 3명)을 제안한다.
소유자가 양쪽 역할을 시험하면 연결 오류를 찾을 수 있지만 독립 사용자 관찰을 대체하지 않는다.
시장 규모 추정이나 통계적 성공률을 주장할 표본은 아니다.

합성 과제: 금요일까지 웹 초안을 요청하고, 모바일 담당·일정은 미정인 업무 전달.
진행자는 버튼 이름이나 사용 순서를 먼저 가르치지 않는다.

1. 발신자가 자신이 무엇을 해야 하는지 설명하고 초안을 준비한다.
2. 미정 사항을 확정으로 바꾸지 않고 검토·확정·링크 전달을 완료한다.
3. 수신자는 요청·기한·미정 사항을 전달본에서 찾아 설명한다.
4. 자신의 AI로 질문하고 검사할 답변을 선택한다. 미연결 기능은 실행 성공으로 채점하지 않는다.
5. INDETERMINATE와 검증 범위를 자기 말로 설명한다.
6. 발신자가 링크 해제와 전체 삭제의 차이를 설명한다. 실제 파괴 작업은 필요 없다.

관찰 지표: 과제별 도움 없는 완료 여부, 첫 클릭 방향, 멈춘 지점·되돌아간 횟수,
출처/검증 범위의 오해, 발신자가 예상한 후속 질문 부담. 시간은 보조 지표다.
가설적 통과 기준은 안전 범위 오해 0건, 핵심 과제의 진행자 개입 없이 완료다.
미달 시 원인에 맞춰 문구·위계·단계 구조를 바꾸고 같은 과제를 재검증한다.

인터뷰·기록 방식은 실제 조사 착수 전에 사용자와 정한다. 지금은 참가자 접촉,
녹화, 개인 업무 자료 수집이나 새 분석 도구를 활성화하지 않는다.
